# Device feature topic rebased to v0.82.0

This topic is a real rebase of `rebuild/v0.81-devices` (`17dcf446`) onto upstream
stable `v0.82.0` (`d951ef9`). The original three commits (`04e98b6`, `e6986b7`,
`17dcf44`) are retained in order with their authorship and source provenance.
This branch contains only device features. Gesture/touchscreen and source
lifecycle/IIO topics must be validated independently and integrated afterward.

## Compatibility resolutions

- **Ultimate 2:** the v0.82 real-controller descriptor replaces the old vendor-only
  descriptor and declares report ID `0x01`. Both physical and virtual inputs now
  use `0x01`; separate constant names intentionally alias that value. This
  supersedes the v0.81 virtual ID `0x04`, while retaining the physical fixture,
  both neutral hat values, signed sticks, production paddle byte mapping and
  digital triggers. Keep upstream corrected trigger-change detection, inverse
  sensor-frame rotation, m/s²/rad/s conversion, persistent target identity and
  source haptic/rumble support. A pure target helper permits hardware-free replay.
- **Legion Go 2:** use the complete upstream frame transformation, including the
  corrected right accelerometer and generation-specific left/center gyro yaw.
  Preserve upstream SI conversion in the source and kernel event filtering.
  Production replay factoring is retained, now with an explicit hardware
  generation parameter. Do not apply the old production sign changes a second
  time over upstream's correction.
- **Generic HID:** keep explicit V2-map fallback for unknown interfaces, dedicated
  native GPD macro driver priority, blocked-device priority, upstream polling
  options, renamed Legion Go S variants and name/kernel-driver/path metadata in
  the pure dispatcher. Win5 `2f24:0137/interface0` and Terrans Force
  `2f24:0135/interface3` remain generic; `2f24:0135/interface1` remains native.
- **Win5 recovery:** retain KeyDelete-only opt-in, monotonically advancing timer
  generations, source-specific mapping checks and duplicate-press containment.
  The ordered in-loop delayed release now uses upstream `MIN_EVENT_TIME` (16ms),
  replacing the removed local `sleep_time` binding. It remains a bounded timing
  workaround, not a scheduler redesign.
- **Configurations:** preserve required_keys parser/matching/schema; Win5 HID and
  watchdog configuration; IPASON/TF profiles, maps and autostart. Upstream OXP3/X2
  profiles remain byte-identical, with no invented touchscreen mapping. This
  topic intentionally does not add the separate Win5/X1 touchscreen feature or
  MSI/IIO lifecycle configuration.

## Review correction: queued translated re-press spacing

Independent review identified a production timing regression from retaining
upstream's release-only `!event.pressed()` gate. With mapped DOWN/UP/DOWN queued
at 0/1/2ms, the release was delayed to about 17ms but the re-press could follow
immediately, allowing a state-coalescing HID target to miss the neutral state.

The translated-event timing helper now applies the existing in-loop 16ms wait
to either edge while its capability is recent. It retains the original FIFO
`RemoveRecentEvent` callbacks. A hardware-free Tokio paused-clock replay uses
that production helper and command queue, asserts DOWN/UP/DOWN before the first
removal callback, and verifies actual output times 0/17/33ms and both inter-edge
gaps. Tokio `test-util` is enabled only as a development dependency. Upstream
`write_send_event` behavior and the gesture topic are unchanged. Independent
review confirmed that this replay resolves the reported P2 without an additional
blocking finding.

This is a bounded production-compatibility fix. The pre-existing unversioned
recent-marker removal can clear a newer marker under other arrival schedules;
that scheduler behavior is not redesigned here.

## Remaining hardware validation

No physical hardware was attached. Verify U2 kernel/Steam/SDL recognition,
firmware report IDs, paddle/trigger behavior, sensor orientation and rumble/haptic
timing; Go2 sensor orientation and kernel-filter behavior; Win5 missing-release
recovery; and IPASON/TF button mappings/autostart. The Win5 350ms KeyDelete timeout
can still expire a legitimate opted-in hold without repeat, spawns one timer per
refresh, and only synthesizes releases for single-source mappings. The in-loop
release-order delay may hold up other source events for 16ms.
