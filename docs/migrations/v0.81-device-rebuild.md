## Compatibility adaptations

- Generic HID is a fallback for unknown interfaces with an explicit V2 source
  capability map. The native GPD `2f24:0135/interface1` driver remains preferred;
  Win5 `0137/interface0` and TF `0135/interface3` remain generic. All existing
  upstream source polling options are preserved. Invalid bit offsets are skipped
  to prevent an unchecked shift from panicking.
- The Ultimate 2 physical source keeps input report ID `0x01`, as shown in the
  physical capture already recorded in upstream. The virtual target uses a separate
  `0x04` constant matching its descriptor. Both centered hats (`0x0f` physical,
  `0x08` virtual) decode; neither has directional bits. Target paddle mapping,
  signed stick denormalization, and digital trigger support are rebuilt.
- The original Win5 watchdog applied to all mapped keys, truncating ordinary
  no-repeat holds. It also reused timer generation 1 after release, letting old
  timers release a new press. The rebuild explicitly opts in only Win5 KeyDelete
  via `options.translatable_stale_keys`, with monotonically advancing tokens.
  Other keys/devices do not acquire the timeout. The 350ms recovery is still a
  firmware heuristic: a legitimate opted-in KeyDelete hold without repeat will
  expire. A task is still spawned for each refresh; the original in-loop 4ms
  ordering delay is retained and may delay other sources. This is bounded
  containment, not a scheduler redesign. Recovery only emits single-source
  mapping releases; opt-in keys should not be used for arbitrary chords.
- required_keys is represented in the shipped composite schema, as is the new
  explicit watchdog opt-in. Bitmap parsing has pure word-order/bounds tests.
- Go2 translation is factored only enough for hardware-free axis replay, keeping
  upstream kernel event filtering and device polling unchanged.

## Validation at feature commit

- `cargo fmt` with Rust 1.92; unrelated upstream formatting changes reverted
- `git diff --check`

Added 18 Rust regression tests:

- GPD native/generic/blocked interface dispatch, shared touchpad device names, and
  Microsoft UHID kernel-driver/path matching
- required_keys bitmap and legacy/new configuration parsing
- HID Win5 press/repeat/release and first-pressed/short TF reports
- HID report-ID, value and bit filters; invalid bit offset
- physical U2 capture unpack/repack and target descriptor/default bytes
- U2 cardinal/diagonal hat transitions, stick endpoints/center, paddles/triggers
- watchdog stale-generation cancellation and repeat refresh; Win5-only opt-in
- Go2 left/right/center accel+gyro signs and kernel capability filtering

Parent integration verification on 2026-10-09: cargo compilation passed and the
integrated suite passed all 66 tests in both library and binary harnesses, plus
4 documentation tests. This covers the 18 device regression tests above. Strict
all-targets Clippy identified a collapsible nested UHID dispatch condition; the
follow-up commit combines it without changing behavior. Final strict Clippy and
post-fix integration verification remain owned by the parent integration branch.

There is no attached physical hardware. Real-device protocol,
firmware timing, suspend/resume, kernel-filter behavior, UHID/Steam recognition,
force feedback, sensor orientation, and autostart still need hardware validation.
The U2 physical fixture is an existing upstream capture, not a newly captured
sample; support for other source firmware report IDs remains unverified.
