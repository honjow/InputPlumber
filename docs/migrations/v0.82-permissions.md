# Scoped permission restoration on v0.82

This topic is a direct rebase of `rebuild/v0.81-permissions` (`dafa255`) from
upstream v0.81.0 onto upstream v0.82.0 (`d951ef9`). The original three commits
remain separate and retain their original messages for provenance:

- `9fa3ae2` -> `ef264d3`: preserve scoped best-effort restoration
- `03329d0` -> `eec167c`: bind restoration retries to original node identity
- `dafa255` -> `8e98295`: explicit octal test literal

The upstream v0.82 early rule tried to jump to a label in the separate late
rule file. udev resolves `GOTO` only within the same file, so this jump was
invalid and could not skip intervening rules. The compatibility fix removes
that jump and its unused late-file label. The existing `50` and `96` stages
still match independently in normal rule-file order; their permission, ACL,
symlink and move actions are unchanged. No new permission or uaccess strategy
is introduced. See the [systemd v257 label resolution code](https://github.com/systemd/systemd/blob/v257/src/udev/udev-rules.c#L1238-L1265).

Restoration still changes only nodes tracked by this process, uses the exact
saved mode, verifies device, inode and rdev identity, retains failed records for
retries, and refuses stale records for replacement nodes. No global mode-000
scan or broad chmod fallback is added.

Validation uses only temporary regular files. The five restoration regression
cases cover exact-mode restore, unmanaged-node exclusion, failed-restore retry,
tracked-name validation, and inode replacement. Generated-rule tests cover
forward file-local jumps and unchanged two-stage actions. An explicit parser
regression validates both generated files with `udevadm verify --no-style` for
all hide-flag combinations across input and hidraw examples, and checks that
the old cross-file jump is rejected. Run it on a system with `udevadm verify`:

```sh
cargo test --bin inputplumber udev::rules_test -- --include-ignored
cargo test --bin inputplumber udev::restore_test
```

The two pure rule tests run by default without `udevadm`; the parser test is
explicitly ignored unless requested with `--include-ignored`, so it does not
add a system-tool dependency to normal CI. Cloud validation with Rust 1.92 and
udevadm 257 passed all three rule tests (12 generated early/late pairs plus the
cross-file-jump negative control), the five restoration tests, all-target
`cargo check`, and all-target `cargo clippy -- -D warnings`. Changed-file
formatting passes; whole-repository formatting still has the same 25 unrelated
file differences as the unmodified `718af48` base.

Only temporary regular files are written. No live `/dev` node, udev reload or
trigger, daemon, or running service is touched.

Independent Rust 1.92 validation is recorded with the final topic commit/tree
in the integration report. This topic is merged independently before device,
source/IIO and gesture features; it does not depend on those topics.
