# Touchscreen gesture topic rebase onto v0.82.0

## Scope and provenance

This is an independent `rebuild/v0.82-gestures` topic based on upstream stable
`d951ef9` (`v0.82.0`). It rebases the three commits from the original
`rebuild/v0.81-gestures` branch, rather than importing the production integration
merge or unrelated device/IIO changes.

| Original topic commit | Rebased commit | Purpose |
| --- | --- | --- |
| `64a8c4e` | `9edad2e` | Gesture capabilities, configuration/schema, touch detection/replay, profile mapping and scoped target pulses |
| `d0859b7` | `8b2ad8a` | Exhaustive touch-button value translation |
| `5494de7` | `a74ad05` | evdev replay tests using the pinned raw event-code API |

Compatibility commit `415fdeb` adds the asynchronous creation and cleanup
regressions below. Win5 stale-release watchdogs, generic HID support, IIO
suspend/resume and sensor corrections belong to their separate topics.

## Preserved behavior and upstream integration

- Keep gesture capability parsing, exact-region-before-wildcard profile mapping,
  source metadata and default Guide/QuickAccess mappings.
- Keep edge-swipe detection, orientation handling, touch suppression/tap replay,
  multitouch and timeout guards, and Win5/X1 grabbed touchscreen opt-ins.
- Retain v0.82's `config.imu.mount_matrix` and values for X1; the gesture topic
  only adds its touchscreen source. Do not restore the obsolete `iio` matrix.
- Retain v0.82 asynchronous target creation and persistent device identity. The
  touchscreen target is still retained across target/profile switches for an
  explicitly grabbed source; keyboard/mouse ownership is unchanged.
- Retain upstream SI accelerometer/gyroscope capabilities and source identities;
  do not reintroduce removed legacy `Gamepad::Gyro/Accelerometer` conversions.
- Keep the gesture-only 80 ms press/release scheduler. Ordinary physical inputs
  remain immediate and take ownership from a pending synthetic pulse. Existing
  target macro/chord scheduling is not globally debounced.

## Narrow compatibility fixes

- Clone the manager sender before constructing targets: v0.82 now also stores
  that sender in the composite device.
- An attachment may arrive before the asynchronous creation-completion message.
  Completion now queues only targets not already attached, so later target
  requests do not wait forever for a duplicate attachment. Creation failure
  still allows the latest deferred request to proceed.
- ClearState releases active gesture-owned buttons before discarding their
  pending up events. This covers keyboard and mouse targets as well as stateful
  HID targets, without synthesizing releases for physical input.
- Target shutdown runs once through a cleanup epilogue, including failed output
  forwarding, scheduled input and gesture writes. A failed synthetic release
  cannot skip device shutdown. Stop no longer invokes USB/UHID stop twice.

## Validation

Validation of the source in `415fdeb` on 2026-10-14 uses Rust 1.92, a dedicated
target directory, and `cargo clean -p inputplumber` before compiling the topic.
The final documentation commit does not change that validated source.

Passed:

- `cargo check --locked`
- `cargo test --locked`: 44 library tests, 44 binary tests and 4 documentation
  tests; no failures or ignored tests.
- `cargo clippy --locked --all-targets -- -D warnings`
- `rustfmt --edition 2021 --config skip_children=true --check` for every Rust
  file changed by this topic.
- `git diff --check`

Unmodified v0.82 has broader formatting differences under this Rust version;
this topic formats only the Rust files it changes.

Nine new hardware-free tests cover both asynchronous attachment orderings,
failed creation/latest deferred request, keyboard/mouse ClearState, physical
ownership, single-stop/error cleanup, and stable upstream identity vectors.
The original gesture detection, replay, mapping and pulse tests remain present.

Schema comparison against unmodified v0.82:

- Win5: no validation errors; grabbed touchscreen present.
- X1: the same one upstream Udev additional-properties error remains
  (`id_vendor`, `id_product`, `interface_number`).
- Default profile: the same four upstream LeftStickDial/RightStickDial enum
  errors remain. The two gesture-only mappings validate successfully.
- All schema files parse as JSON; this topic introduces no additional schema
  validation errors in those affected configurations.

No daemon or input device was started, and no hardware validation is claimed.
Real touchscreen grab/replay, rotated X1 gestures, Steam/Decky target switching,
USB/UHID teardown and suspend/resume still need physical-device validation.
Existing unrelated macro ClearState and grab-fallback reliability issues are
not redesigned by this compatibility rebase.
