## Feature mapping and v0.82 adaptations

- Keep the source `Suspend`/`Resume` client API, same-batch transitions,
  idempotence, blocking command wait while suspended, logind forwarding, and
  ROG Ally remap reapplication. Preserve upstream persistent target IDs and
  target-before-source resume ordering.
- Keep fresh fd acquisition after lifecycle changes and polling; never hold a
  borrowed descriptor across driver reconstruction. Preserve finite, rounded,
  saturating fd wait timeouts and terminal poll-event rejection.
- Replace libiio completely with the v0.82 sysfs scan-layout/raw-buffer design.
  The raw file is opened with `O_NONBLOCK`; partial records remain private until
  complete. `EAGAIN` and `EINTR` produce no sample; EOF and permanent errors
  propagate. There is no hidden indefinite fd wait in the driver.
- Keep production `iio.use_buffer: false`. Direct sysfs discovery requires
  neither scan elements nor a devnode/trigger and is the fallback if buffer
  setup fails. The AMD SFH MSI profile keeps this setting for both sensor
  sources, with upstream mount matrices and SI correction factors intact.
- Every configured buffer, including hardware-triggered buffers, has owned
  cleanup. Suspend/stop/drop and failed setup attempt to disable its buffer and
  scan channels and unbind its trigger. Dedicated hrtimer triggers are removed
  only after verified buffer disable and verified unbinding; failures are logged
  and retain the directory. Scan-channel reset is verified before enabling the
  exact decoded layout.
- Follow v0.82's dedicated per-device BMI/ICM hrtimer on both cold open and
  resume. This supersedes the v0.81 cold-open hardware preference while
  retaining its software-trigger resume safeguard. Unavailable hrtimer falls
  back to a matching hardware trigger, then direct sysfs. Hardware trigger
  discovery does not require `trigger_now`, which hardware triggers need not
  expose; unrelated triggers are not intentionally selected.
- Use upstream `config.imu` mount matrix/sample rate/correction precedence and
  SI `common::translate_events`, retaining deprecated IIO-field fallback.
  Acceleration remains m/s² and angular velocity rad/s; old UHID-LSB and
  degrees-per-second source multipliers are not revived. Corrections are
  applied exactly once. Split accel/gyro devices advertise only their actual
  capabilities. Resume retains the event filter and all sensor configuration.
- Preserve unchanged-sample suppression and direct-sysfs slow-read backoff.
  The source retains a finite 2.5 ms pacing floor when no fd exists, so failed
  recreation cannot become a zero-rate busy loop. Sysfs reads are paced to the
  negotiated rate; fd-driven buffers are paced by readiness.

## Decoder compatibility fixes

The v0.82 decoder's `raw - offset` expression is corrected to `raw + offset`.
The Linux [IIO sysfs ABI](https://www.kernel.org/doc/Documentation/ABI/testing/sysfs-bus-iio)
explicitly defines offset addition before scaling, including `in_accel_offset`
and per-axis offsets. Its `in_accel_*_raw` and `in_anglvel_*_raw` entries define
m/s² and rad/s respectively. Tests replay a negative shifted raw value with a
nonzero positive offset, and direct sysfs values with fractional offsets and
per-axis scales. Buffered discovery also retains the old libiio shared offset
behavior: per-axis offset takes precedence, then `in_accel_offset` or
`in_anglvel_offset`, then zero. A fixture verifies raw 10, shared offset 2 and
scale 0.5 produce 6; a per-axis offset of -4 overrides it and produces 3.

### Real sysfs trigger unbinding

The unbind payload is one newline byte, not an empty Rust slice. Empty
`write_all` performs no write and therefore never invokes a sysfs store handler;
truncating a regular test file cannot establish kernel unbinding.

The actual Linux v6.12 implementation is
[`current_trigger_store` and `iio_trigger_acquire_by_name` in
`drivers/iio/industrialio-trigger.c`](https://github.com/torvalds/linux/blob/v6.12/drivers/iio/industrialio-trigger.c).
The lookup uses `sysfs_streq`; this is newline-tolerant comparison rather than
an explicit `strim` call. The
[`sysfs_streq` implementation](https://github.com/torvalds/linux/blob/master/lib/string_helpers.c)
treats a final newline followed by NUL as equivalent to string termination.
A lone newline does not match a named trigger, so lookup returns NULL. The store
then sets `indio_dev->trig` to NULL and releases the old trigger reference.
`current_trigger_show` returns zero bytes for the unbound state. The store
rejects changes while a triggered buffer remains enabled (`EBUSY`).

Accordingly, dedicated-trigger removal requires successful buffer-disable
write/readback, a nonempty newline write, and empty trigger readback. If any
step fails, the trigger directory is retained and the failure logged. The new
writer-spy test verifies that a write really occurs with exactly one newline;
separate fixtures verify readback, both cleanup paths, and preservation after
buffer-disable/unbind failure. These tests complement the kernel-source
inspection; they are not a claim of real-device testing.

The raw-layout path retains upstream support for mixed 8/16/32/64-bit storage,
endianness, signedness, shifts, alignment and timestamps. Invalid and unsupported
scan formats fail setup rather than panicking or silently misdecoding; a usable
sysfs source can then take over. Invalid/nonfinite requested or advertised sample
rates cannot panic duration conversion.

The isolated test build uses a separate Cargo target directory, with
`CARGO_BUILD_JOBS=2`; no other topic's package artifacts are used as evidence.

Coverage includes:

  event-filter retention, actual Unix-socket fd replacement after resume;
- finite fd timeout boundaries, terminal flags and real socket hangup;
- nonblocking open, empty/partial/reassembled records, EAGAIN/EINTR and EOF;
- scan endianness/shift/signedness/mixed-width replay and malformed formats;

  scaling, filtering and changed-sample suppression;

  unavailable-hrtimer fallback, failed setup rollback and stale-scan cleanup;

  and `use_buffer` schema presence.

## Remaining hardware acceptance and reliability limits

1. Actual hardware is untested in this cloud environment. Record kernel and
   firmware, verify axes/units and event rate, then exercise 20 suspend/resume
   cycles on representative BMI/ICM, Intel HID Sensor Hub, AMD SFH and Ally
   hardware before deployment.
2. Resume still waits three seconds and attempts reconstruction once. A failed
   reconstruction leaves no driver and logs the failure; repeated retry and
   reconnect policy are not added here.
3. Direct sysfs reads and the HID Sensor Hub sample-kick read can block in the
   kernel. Raw-buffer fd reads themselves are nonblocking, but this does not
   turn slow sysfs operations into cancellable operations. The existing slow
   direct-sysfs backoff remains.
4. Source suspend is queued, not acknowledged after hardware teardown. The
   logind listener still has no inhibitor/reconnect loop; the upstream systemd
   suspend hook remains. Duplicate source hooks are idempotent, while broader
   target-level ordering follows upstream.
5. Kernel-reported rates and dedicated trigger rates may differ if the kernel
   rejects or rounds a rate write. Hardware-specific firmware/scale correction
   assumptions in device profiles still need hardware verification.
6. If buffer disable or unbinding cannot be verified, including after device
   removal makes the sysfs paths disappear, owned hrtimer configfs directories
   are deliberately retained. Normal cleanup removes them; automatic reclamation
   after unverified cleanup is not claimed.
7. Raw-buffer group scales retain upstream's uniform-within-group assumption
   and integer offset metadata. Direct sysfs uses per-axis scale and fractional
   offset values. Unsupported scan formats use sysfs when possible rather than
   claiming broader raw-decoder support.
